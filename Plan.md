# План тестирования мобильного приложения «Мобильный хоспис»
## Объект тестирования
Мобильное приложение «Мобильный хоспис» под ОС Android. Приложение предоставляет функциональность для работы с новостями хосписа и включает в себя:
* информацию о новостях и функционал для работы с ними;
* тематические цитаты;
* информацию о приложении.
## Тестовые данные
Предоставлены данные для авторизации:
* логин `login2`
* пароль `password2`
## Тестируемые функциональности
Тестированию подлежат следующие компоненты приложения:
### Экран авторизации в приложении `Authorization`
* поля ввода логина `Login`;
* поле ввода пароля `Password`;
* кнопка `SIGN IN`.
### Топбар приложения
* меню приложения с выпадающим списком с пунктами `Main` и `News`;
* кнопка перехода на экран цитат `Love is all` (символ в виде бабочки);
* кнопка учётной записи (символ человека) для выпадающего меню с пунктом `Log out`.
### Главный экран `Main`
* кнопка сворачивания-разворачивание блока новостей;
* кнопка `ALL NEWS` для перехода на экран новостей `News`;
* сворачивание-разворачивание новостей в плашках опубликованных новостей.
### Экран новостей `News`
* сворачивание-разворачивание новостей в плашках опубликованных новостей;
* кнопка сортировки новостей (символ стрелки вверх и стрелки вниз;
* кнопка перехода на экран фильтрации новостей `Filter news` (символ с переключателями);
* кнопка перехода на экран управления новостями `Control panel` (символ «лист и карандаш»).
### Экран фильтра новостей `Filter news` при переходе с экрана `News`
* поле `Category` с выпадающим списком категорий новостей;
* поле `DD.MM.YYYY` для выбора начала периода;
* поле `DD.MM.YYYY` для выбора конца периода;
* кнопка `FILTER` для применения настройки фильтра и перехода на экран `News`;
* кнопка `CANCEL` для отмены настройки фильтра и перехода на экран `News`.
### Экран панели управления `Control panel`
* список всех новостей;
* кнопка сортировки новостей (символ стрелки вверх и стрелки вниз);
* кнопка перехода на экран фильтрации новостей Filter news (символ с переключателями);
* кнопка создания новости (символ «плюс в круге»);
* плашки с информацией о создании новости с кнопками сворачивания-разворачивания, удаления (символ мусорной корзины), редактирования (символ «лист и карандаш»);
* кнопка удаления новости (символ мусорной корзины) с диалоговым окном подтверждения выхода и кнопками:
1. `CANCEL` для возврата на экран `Control panel`;
2. `OK` для удаления новости и возврата на экран `Control panel`.
### Экран фильтра новостей `Filter news` при переходе с экрана `Control panel`
* поле `Category` с выпадающим списком категорий новостей;
* поле `DD.MM.YYYY` для выбора начала периода;
* поле `DD.MM.YYYY` для выбора конца периода;
* чекбокс `Active`;
* чекбокс `Not active`;
* кнопка `FILTER` для применения настройки фильтра и перехода на экран `News`;
* кнопка `CANCEL` для отмены настройки фильтра и перехода на экран `News`.
### Экран создания новостей `Creating News`
* поле `Category` с выпадающим списком категорий;
* поле ввода заголовка `Title`;
* поле `Publication date` с формой выбора даты;
* поле `Time` с формой выбора времени;
* поле ввода текстового описания `Description`;
* переключатель статуса `Active`;
* кнопка `SAVE` для сохранения созданной новости;
* кнопка `CANCEL` для отмены создания новости с диалоговым окном подтверждения выхода и кнопками:
1. `CANCEL` для возврата к созданию новости;
2. `OK` для перехода на экран `Control panel`.
### Экран редактирования новостей `Editing News`
* поле `Category` с выбранной категорией из выпадающего списка;
* поле `Title` с введённым заголовком новости;
* поле `Publication date` с заполненной датой;
* поле `Time` с заполненным временем;
* поле `Description` с заполненным описанием;
* переключатель статуса `Active`;
* кнопка `SAVE` для сохранения отредактированной новости;
* кнопка `CANCEL` для отмены редактирования новости с диалоговым окном подтверждения выхода и кнопками:
1. `CANCEL` для возврата к редактированию новости;
2. `OK` для перехода на экран `Control panel`.
### Экран цитат `Love is all`
* плашки цитат с кнопками сворачивания-разворачивания.
### Учётная запись (символ человека)
* кнопка `Log out` для выхода из учётной записи.
## Типы тестирования
* **Исследовательское тестирование**: на начальном этапе в связи с отсутствием ТЗ и документации о проекте предполагается изучить структуру приложения, выявить скрытые особенности и дефекты.
* **Функциональное тестирование**: проверка соответствия работы функций приложения ожидаемому поведению, в том числе негативное тестирование.
* **Тестирование пользовательского интерфейса** (UI) - проверка корректности отображения элементов.
* **Тестирование удобства использования** (usability) - оценка интуитивности навигации, понятности элементов управления, доступности основных функций.
* **Тестирование безопасности** - проверка защиты авторизационных данных, невозможности несанкционированного доступа к функциям без входа, корректность завершения сессии.

## Последовательность тестирования
1. Ручное тестирование — исследовательское тестирование для формирования понимания тестируемой системы, проверка функциональностей и элементов, не подлежащих автоматизированному тестированию.
2. Составление чек-листа проверки приложения.
3. Описание тест-кейсов.
4. Автоматизированное тестирование.
5. Составление отчётной документации по результатам тестирования.
## Инструменты тестирования
* `Android Studio`. Интегрированная среда разработки (IDE) для приложений на платформе Android, запуска эмулятора, просмотра структуры UI через `Layout Inspector`.
* Эмулятор `Pixel 4` API 29 (Android 10). Целевое устройство для прогона тестов.
* `Espresso`. Фреймворк для автоматизации тестов мобильных приложений на платформе Android.
* `Java JDK 11`. Набор инструментов разработки на языке программирования Java, используется для создания автотестов.
* `JUnit 4`. Фреймворк для организации и запуска тестов на языке Java.
* `Gradle`. Система сборки и управления проектами Java.
* `Allure Framework`. Инструмент формирование наглядных отчётов о результатах прогонов.
* `GitHub`. Хостинг проектов, использующих систему контроля версий `Git`.

## Риски автоматизации
* **Отсутствие документации приложения**. Неоднозначность понимания функциональностей приложения и всех его возможностей. Для минимизации рисков предполагается провести исследовательское тестирование перед началом написания автотестов.
* **Отсутствие технического задания**. Неоднозначность ожидаемых результатов, возможна неверная расстановка приоритетов. Для минимизации рисков предполагается провести исследовательское тестирование перед началом написания автотестов.
* **Возможные изменения приложения**. Необходимость переписывать тесты при внесении изменений в приложение. Для минимизации рисков предполагается использовать поиск элементов по тестовым ID.
